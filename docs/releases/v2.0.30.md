# G-LLM Client 2.0.30 Windows candidate

Application version `2.0.30`, Windows x64 MSIX `2.0.30.0`.

**简体中文**

可在 Windows 上接管选定的现有浏览器窗口，沿用当前标签页，读取网页、点击控件、填写普通表单、导航和切换标签页。也可在选定的 Windows 应用窗口中读取控件、点击、输入、按键和滚动。两项权限独立开启，每次操作均需确认。支持图像输入的模型可使用窗口截图。登录与个人额度沿用 [2.0.29](v2.0.29.md)。

**English**

On Windows, the assistant can work in a selected existing browser window to read the page, click controls, fill ordinary forms, navigate and switch tabs. It can also read controls, click, type, use shortcuts and scroll in a selected Windows application. Each capability has its own setting and every action requires confirmation. Models with image input can use a window screenshot. Personal sign-in and allowance features are carried forward from [2.0.29](v2.0.29.md).

The Windows SDK built `G-LLM-Client-2.0.30-x64.msix` (321,505,433 bytes) from source commit `bca3ea87ebac48fdb6701ee808daa052d51d72d5`. SHA-256: `e31a0a9c0003ace014bdbac8f8a32009ffb48e2473b648ac84378e9b828a29c8`. The unsigned Store candidate contains the expected `gllm` protocol and the Windows window control helper. The package contains the same app payload used for account integration tests. No Store submission has been made for this candidate.

Production build, 238 regression tests (11 platform skips), nine focused permission and workspace routing tests, embedded browser integration, and six packaged account integration phases passed. The Windows helper compiled from the packaged resource. Dependency audit reported no known vulnerabilities. The foreground desktop test stopped at the fixture approval because the test runner could not direct a click to its window. Desktop input and external Chrome, Edge and 360 flows still need interactive Windows acceptance.
