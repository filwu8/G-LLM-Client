# G-LLM Client 2.0.32 Windows update

Application version `2.0.32`, Windows x64 MSIX `2.0.32.0`. Store identity, publisher, application ID, `gllm` protocol and storage paths are unchanged.

**简体中文**

- 工作区顶栏新增 Agent 权限模式切换，图标化显示三种状态：逐次请求批准、只读并允许写入授权目录、完全访问。新建会话选定完全访问后会保持该模式，不再中途退回逐次批准。
- 完全访问仍以用户授权的文件夹为边界：授权目录内可写，目录外只读，host 脚本和越界写入仍逐次确认。
- 未完成任务的提示新增“取消任务”，确认后清除已保存的进度，已产生的文件改动保留。
- 修复若干导致任务中断的问题：仓库根目录参数被误判越界、Git 索引锁争用导致连续失败、进度保存瞬时失败终止任务、把“不要修改任何文件”误判为写操作。
- 降低工作区工具栏首次点击的响应延迟。
- 依赖更新至 i18next 27、react-i18next 18、React 19.3、mermaid 12、lucide-react 1.73；`@napi-rs/canvas` 统一到 1.1.1，安装包不再携带重复的原生二进制。

**English**

- The workspace toolbar adds an agent permission mode switch with three icon states: ask for each action, read-only with writes allowed inside authorized folders, and full access. A conversation started in full access keeps that mode instead of dropping back to per-action approval.
- Full access still stops at the folders the user authorized: writes are limited to those folders, everything outside is read-only, and host scripts or out-of-scope writes are still confirmed each time.
- The unfinished-task notice gains a Cancel action that discards saved progress while keeping files already changed.
- Fixes several causes of interrupted tasks: the repository root argument was rejected as out of scope, Git index-lock contention failed repeatedly, transient progress-save errors aborted a task, and a request not to modify any file was misread as a write action.
- Lowers the first-click latency of the workspace toolbar.
- Updates dependencies to i18next 27, react-i18next 18, React 19.3, mermaid 12 and lucide-react 1.73; `@napi-rs/canvas` is unified on 1.1.1 so installers no longer carry a duplicate native binary.

The unsigned Store package keeps identity `GPROPHETLIMITED.G-LLMClient`, publisher `CN=47A4A51B-7614-4112-BA6F-13F6A84141F9`, application ID `GLLMClient` and the `gllm` protocol at version `2.0.32.0`. Unpacking the finished package reproduced the same `AppxManifest.xml` values, and the packaged `app.asar` and `G-LLM-Client.exe` SHA-256 digests match `dist/win-unpacked`.

The package is 16.1 MB smaller than `2.0.31` because `@napi-rs/canvas` now resolves to a single 1.1.1 native binary set instead of shipping both 0.1.80 and 1.1.1 for every platform.

TypeScript, `i18n:check` (1343 keys, 2 locales) and the three-stage production build passed, and `verify-main-bundle` validated 15 main-process bundles. The regression suite ran 329 tests with 313 passing, 11 skipped and 5 failing; all five failures are Windows AppContainer sandbox cases (`workspaceDiagnostics`, `workspaceNative`, `workspaceSandbox`) that report `Sandbox execution failed` on this test host, involve no product code, and fail identically before these changes.

The package was submitted to Partner Center as Store submission 7 on 2026-11-20, passed certification, was signed by Microsoft and is live in the Microsoft Store the same day. It has been installed from the Store as `GPROPHETLIMITED.G-LLMClient_2.0.32.0_x64__e9rwfmt1kwxfa` with `SignatureKind` `Store` and `Status` `Ok`, and the in-package `app.asar` and `G-LLM-Client.exe` still hash to the values built locally, so signing changed the signature but not the payload. The `gllm` protocol is still unexercised against the Store build.

## Store submission

Submission 7 (`1152921505702454189`) replaced `G-LLM-Client-2.0.31-x64.msix` with the `2.0.32.0` package, which Partner Center validated on upload. The `2.0.31` package was dropped from the submission because Partner Center offers the higher version to the same device family; existing installs upgrade through it.

The "What's new in this version" text was replaced for all three listings (`en-us`, `zh-cn`, `zh-hans-cn`) with the release notes above. Pricing and availability, properties, age rating and submission options carried over unchanged from submission 6.

Upload raised a `runFullTrust` restricted-capability notice. The capability is declared by the desktop bridge manifest and is already approved for the published `2.0.31` build, so no new approval is pending.

Install acceptance covered the manifest as well: identity `GPROPHETLIMITED.G-LLMClient`, publisher `CN=47A4A51B-7614-4112-BA6F-13F6A84141F9`, version `2.0.32.0`, application ID `GLLMClient`, the `gllm` protocol and `internetClient` + `runFullTrust` capabilities all survived certification unchanged.

One install-side issue is worth recording. The machine that performed acceptance had `2.0.30.0` installed since 2026-11-10 and never received `2.0.31` or `2.0.32` through Store auto-update, even though the catalog had been serving `2.0.32` since 2026-11-20T01:14:43Z. No auto-download policy was set, the deployment services were running, the platform was within the supported range, and the deployment log held no attempt for this package at all. Uninstalling and reinstalling from the Store installed `2.0.32.0` immediately, so the gap was in update delivery rather than in the package.
