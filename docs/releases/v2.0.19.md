# G-LLM Client V2.0.19

V2.0.19 聚焦真实生图工作流：更准确地理解用户意图，在多轮对话中延续原始需求与参考图片，并让保存、预览、等待反馈和本机统计形成完整体验。

## 更可靠的生图编排

- 区分“请求生成图片”与评价、质疑、询问图片等意图，避免用户只是讨论图片时误触发生图。
- 用户继续修改上一张图时，自动携带最近的原始需求和参考图片，不必每轮重新描述。
- 支持参考图的 Responses `image_generation` 路由会接收实际图片输入，而不是只收到文字提示。
- 当供应商仅支持 `/images/generations`、不支持参考图编辑时，明确告知能力限制，避免生成一张看似参考原图但实际没有参考的图片。
- 生图请求仍会根据供应商与模型能力动态选择直接 Image API 或 Responses 生图工具。

## 图片保存与对话预览

- 图片另存为的预填文件名加入毫秒级本地时间戳，连续生成和保存多张图片时不易误覆盖。
- 用户发出的图片在对话中采用紧凑、等比例的预览尺寸；大图会缩小，小图保持自然尺寸，点击后仍可查看完整大图。
- 修复图片预览按钮误继承圆形删除按钮样式导致的重复圆形遮罩。

## 更自然的交互反馈

- 用户明确要求“简短”“一句话”或“一行”时，客户端会把该格式要求传递给模型，不再机械追加“结论、依据、下一步动作”三段式。
- “正在等待模型响应”的扫光周期由 1.8 秒放慢至 3.6 秒，并采用渐入渐出节奏，减少快速闪动带来的干扰。

## 本机生图统计

- “数据统计 / 本机使用统计”新增成功生成图片数量。
- 普通聊天一次生成多张图片会逐张计数，目标模式和工作区中成功完成的 `generate_image` 调用也会计入。
- 失败请求与用户上传的图片不会误计；现有历史本地对话会自动回溯统计，无需迁移数据。
- 日期活动提示会同时显示当天成功生成的图片数量。

## 更新方式

- Windows V2.0.18 用户可由客户端自动下载并安装 V2.0.19。
- Apple Silicon Mac（M1/M2/M3/M4 等）：下载 `G-LLM-Client-Setup-2.0.19-arm64.dmg`。
- Intel Mac：下载 `G-LLM-Client-Setup-2.0.19-x64.dmg`。
- Linux：可选择 `x86_64.AppImage` 或 `amd64.deb`。
- 本版本继续采用无证书发布；Windows/macOS 可能显示未知发布者或安全警告，macOS 与 Linux 仍需手动更新。

## English Summary

G-LLM Client V2.0.19 makes image workflows more dependable. It distinguishes explicit image-generation requests from feedback or questions, carries forward the latest original requirements and reference images in follow-up turns, and sends real reference inputs through compatible Responses `image_generation` routes. Providers that expose only `/images/generations` now report their inability to edit reference images instead of silently producing an unrelated result.

Save Image As suggestions now include a local millisecond timestamp, sent images use compact proportional previews, and an unintended circular preview mask has been removed. Explicit requests for brief or one-sentence answers bypass the old fixed three-part response structure, while the model-wait shimmer is slower and calmer.

On-device usage insights now count successfully generated images from both regular chats and workspace tools. Failed generation attempts and user uploads are excluded, and compatible historical local records are counted automatically.
