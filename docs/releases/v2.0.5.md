# G-LLM Client V2.0.5

本次更新解决旧模型仍残留在客户端、最终请求却找不到可用渠道的问题，并让多个会话可以各自继续生成回复。

## 模型列表始终与网关保持一致

- 官方 G-LLM 模型目录会在启动和使用过程中自动刷新，不再长期依赖旧的本地缓存。
- 已下架、渠道已禁用或没有实际可分发渠道的模型，不再出现在官方模型选择列表中。
- 如果模型在两次目录刷新之间突然失效，客户端会立即重新拉取模型列表，自动切换到当前可用模型并安全重试一次。
- 自动切换后会显示原模型和新模型，便于确认本次请求实际使用的模型。
- 自定义 OpenAI-compatible 供应商继续支持手工填写模型 ID，不受官方 G-LLM 目录限制。

## 多会话可以同时处理任务

- 一个会话正在回复时，可以切换到另一个会话继续提问或整理内容，原回复会在后台继续。
- 助手和会话列表会显示回复中、回复完成和回复失败状态，后台结果不会悄悄丢失。
- 每个会话分别保存草稿、附件、消息引用、知识引用和联网搜索设置，切换时不会互相覆盖。
- 工作区 Agent 的活动记录和授权提示也按会话隔离。

## 稳定性改进

- 删除会话或助手时会同步停止对应的后台请求，避免已删除内容继续写入。
- 快速对话窗口会保护正在流式生成的本地内容，避免被较旧的会话同步事件覆盖。
- 新增模型目录与并发会话状态测试，并通过三平台发布构建检查。

## 使用提示

- 安装后首次使用官方 G-LLM 供应商时，客户端会自动更新模型列表。
- 如果原会话选择的模型已经不可用，下一次请求会自动切换；无需手工删除旧会话。
- Windows 与 macOS 安装包目前仍未进行平台签名，系统可能显示安全提醒；自动下载安装会在签名和 macOS notarization 配置完成后启用。

## 下载选择

- Windows：选择 `G-LLM-Client-Setup-2.0.5-x64.exe`。
- Apple Silicon Mac（M1/M2/M3/M4 等）：选择 `G-LLM-Client-Setup-2.0.5-arm64.dmg`。
- Intel Mac：选择 `G-LLM-Client-Setup-2.0.5-x64.dmg`。
- Linux：可选择 `x86_64.AppImage` 或 `amd64.deb`。

## English Summary

V2.0.5 keeps the official G-LLM model catalog synchronized with actual gateway availability. Removed or unroutable models are filtered out, and a request that encounters a newly unavailable model refreshes the catalog, switches to a current model, and retries once. Custom OpenAI-compatible providers still support manually entered model IDs.

The release also lets responses continue independently across conversations, with per-conversation status indicators, drafts, attachments, references, web-search settings, and workspace activity. Deleting a conversation or assistant now stops its active requests, and Quick Chat protects live streaming state from stale synchronization updates.

Windows and macOS packages remain unsigned during the current transition, so the operating system may display a security warning.
