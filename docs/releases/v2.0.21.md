# G-LLM Client V2.0.21

V2.0.21 focuses on reliable Workspace Agent streaming, tool continuation, and honest delivery status, with additional Windows sandbox and document-reading fixes.

## 工作区 Agent 流式请求与工具续接

- 按 Chat Completions 协议累积分块的 `tool_calls`，保留调用索引、ID、工具名和完整参数；仅在协议确认调用完成后解析并执行。
- 工具结果通过原始 call ID 关联，并以 Chat Completions 格式继续请求；保留 assistant 工具调用、全部工具定义和对话上下文。不会把 Responses API 事件或字段混入 Chat Completions 请求。
- 区分连接/响应头等待、首个流数据、流空闲和整轮超时。SSE 注释心跳（例如 `: PING`）只刷新传输活跃计时，不显示为模型内容；空闲判断不再仅依据是否已输出文本。
- 每轮请求带有 run/request/attempt 标识；发生超时或断连时不自动重放生成请求，工具调用按原始 call ID 去重，降低副作用重复执行风险。
- Windows AppContainer 中的本机工具失败（包括 Python 退出码非零）会作为工具错误交回模型处理，不再冒充上游模型错误或直接丢弃整轮。

## Windows 工作区与交付结果

- 改进 Windows Python 在 AppContainer 下的能力探测、沙箱 helper 启动和 UTF-8 错误输出；组织策略阻止脚本运行时会显示可读错误，不再把乱码 XML 原文铺满对话。
- 工作区每轮实际检查 Python 是否能在所选执行模式启动；不可用时不会把 Python 工具交给模型，也不会偷偷退回无沙箱主机执行。
- 修正交付完成判定：没有满足完成验证的目标会标为未完成，而不是“成功”。不可读取的材料会明确报告；新增标准 `.xlsx` 工作簿读取，扫描版 PDF 仍不具备 OCR。
- 增加流式续接、分块工具参数、SSE 心跳、AppContainer 工具失败续接、重试去重和文档读取的模拟回归测试，并纳入 CI 与发布门禁。

## 其他界面修复

- 修复快速对话窗口导航时序问题，避免窗口加载/导航期间状态竞争。
- 调整模型列表窄布局，避免列表项目挤压、重叠。

## English Summary

V2.0.21 improves Workspace Agent streaming and tool-call continuation. The Chat Completions adapter now assembles streamed tool calls by index, waits for protocol completion before parsing arguments, preserves each call ID, and sends one matching result per call while retaining the assistant tool-call message, all tool definitions, and conversation context. Chat Completions and Responses wire formats remain separate.

Connection/response-header wait, first stream data, stream-idle, and whole-run timeouts are tracked separately. SSE comment heartbeats (such as `: PING`) reset transport-idle timing but are never shown as model content; an active stream is not considered stalled merely because no text has appeared yet. Requests carry run/request/attempt IDs and are not blindly replayed after a timeout or disconnect. Tool calls are deduplicated by their original call IDs to reduce the risk of repeating side effects.

Windows AppContainer tool failures, including non-zero Python exits, are returned as tool errors for the model to handle instead of being misclassified as provider failures or dropping the turn. Windows Python probing, sandbox-helper startup, and UTF-8 error reporting are improved. If Python cannot run in the selected execution mode, it is withheld from the model; the app does not silently fall back to unsandboxed host execution.

Completion verification now prevents an undelivered goal from being marked successful. Workspace reading supports standard `.xlsx` workbooks and reports unreadable sources explicitly; scanned PDFs still require OCR, which is not provided here. Simulated regression tests for stream continuation, fragmented tool arguments, SSE heartbeats, local tool failures, retry deduplication, and document reading run in CI and the release gate. This release also fixes Quick Chat navigation timing and constrained model-list layout.
